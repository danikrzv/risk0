# Risk0 Ethereum MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a working Ethereum mainnet prototype that models curated Morpho lender and borrower positions, visualizes their risk dependencies, runs 30-day scenarios, estimates exit cost through Uniswap, and returns an explainable hybrid `STAY`, `EXIT`, or `UNAVAILABLE` result.

**Architecture:** A Next.js application owns user interaction and graph visualization. A FastAPI service owns external data adapters, SQLite caching, graph construction, scenario propagation, probability estimation, exit-cost calculation, and recommendations. Versioned JSON Schemas in a shared package define the service boundary.

**Tech Stack:** pnpm workspace, Next.js App Router, TypeScript, React, `@xyflow/react`, Vitest, Testing Library, Playwright, Python 3.12, FastAPI, Pydantic v2, HTTPX, SQLAlchemy 2 with SQLite, pandas, Web3.py, pytest, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-07-risk0-mvp-design.md`

## Global Constraints

- Support Ethereum mainnet only (`chainId = 1`).
- Support only the five version-controlled catalog entries from the spec; no wallet discovery.
- Keep the product read-only: no private keys, signatures, approvals, or transaction execution.
- Use a fixed 30-day recommendation horizon.
- Store the Ethereum RPC URL only in `.env`; never expose it to the browser, logs, fixtures, or Git.
- Return only `STAY`, `EXIT`, or `UNAVAILABLE`; missing critical data can never become `STAY`.
- Label empirical probabilities separately from `model-estimated` protocol probabilities.
- Keep raw live snapshots for 24 hours, quotes for 15 seconds, history for 365 days, and the SQLite cache below 100 MB.
- Do not persist user simulations.
- Use `Decimal` for token quantities, USD values, rates, probabilities, and costs; do not use binary floats in domain calculations.
- Every external datum that affects a recommendation carries source, retrieval time, and freshness.

## Review Focus

- Zero, negative, non-finite, or excessively large position inputs must return validation errors; boundary LTV at or above LLTV must be rejected in Task 5 tests.
- Token decimal differences and large 18-decimal values must round predictably without float drift; pin this in Task 5 and Task 9 tests.
- Stale, partial, or conflicting provider data must produce an explicit stale warning, conservative value, or `UNAVAILABLE`; pin this in Task 3, Task 4, and Task 10 tests.
- A removed or inactive curated entity must remain identifiable but analysis must be disabled; pin this in Task 4 tests.
- An expired quote or a quote from a materially older block than the analysis snapshot must be refreshed or yield `UNAVAILABLE`; pin this in Task 9 and Task 10 tests.
